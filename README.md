# batchtrace — 制造业批次追溯核算库

供上层直接调用的 Go 库，账本保存在进程内存中。针对「离线补录的生产领料
只有数量与可能来源、没有准确批号」的场景，在全部合法分配上给出异常批次
流向目标领料的**真实**合计数量上下界，两端各附一份覆盖整份账本的完整
分配作为核查依据。

## 能力

- `NewLedger(batches, issues, confirmations)`：接收一份完整账本
  （单仓库单物料的全部入库批次、全部领料、全部已确认来源记录），
  并做静态校验。
- `(*Ledger).Query(anomalousBatches, targetIssues)`：查询一组异常批次
  流向一组目标领料的合计数量区间 `[Min, Max]` 及两份完整分配依据。
  查询不扣减库存、不固定历史，同一账本上的查询相互独立。

## 业务规则对应

- 数量统一为最小计量单位的正整数（`int64`，全程整数运算，无浮点舍入）。
- 批次在到货时刻（含）起可领用，失效时刻（含）起不可领用；
  候选集合之外的批次不可用于该笔领料。
- 确认记录是下界约束：最终分配不得少于确认量，且不能绕过候选与时间限制。
- 合法分配必须全额满足每笔领料、批次累计分配不超过其数量、
  未使用库存可留存；查询范围之外的领料同样占用库存。
- 整份账本不存在合法分配时，`Query` 返回 `ErrInfeasible`，不伪造区间。
- 上下界分别是全部合法分配上的真实最小/最大值（联合计算，
  不是各目标领料各自取极值再相加）。

## 实现方法

每次查询建模为**带下界的最小费用流**（循环流形式）：

- 下界变换处理确认记录与「领料必须全额满足」，超级源汇判定可行性；
- 求下界：异常批次→目标领料的边费用为 1，最小费用即下界；
- 求上界：改为非异常批次→目标领料的边计费用，
  `上界 = 目标领料总量 − 该最小费用`；
- 求解器为原始-对偶最小费用流（Dijkstra + 势 + 阻塞流），
  费用仅为 0/1，增广轮数少。

## 调用示例

见 `example_test.go`（`ExampleLedger_Query`），可直接 `go test` 运行。

## 测试与性能验证

```sh
go test ./...                 # 全部自动化测试（含完整规模性能验证）
go test -run TestScalePerformance -v .   # 单独查看耗时与内存
go test -bench=BenchmarkScaleQuery .     # 重复测量完整规模查询
```

- 验收场景（两批次 5/3、两目标领料各 3、非目标领料 2 只用第一批）：
  联合区间 `[3,3]`，单查任意一笔 `[0,3]`，依据同时解释非目标领料。
- 边界覆盖：确认来源挤占库存、到货/失效时刻边界、局部候选不足、
  确认量超供应、1e12 级大数量精确计算、查询相互独立。
- 随机小账本与暴力枚举对照（1000 例），验证端点为真实极值。
- 完整规模（500 批次 / 1500 领料 / 30000 候选关系、1e12 级数量）：
  实测一次查询约 0.8 秒（限 10 秒），峰值内存约 22 MiB（限 256 MiB）。
